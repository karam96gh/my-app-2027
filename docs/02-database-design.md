# تصميم المصدر المحلي والحفظ

> الإصدار 1.1. لا قاعدة Supabase أو SQL migrations حالياً. مخطط خادم مستقبلي يحتاج مهمة واعتماداً مستقلين.

## المعمارية

View → GetX ViewModel → Repository → LocalFakeDataSource → تخزين محلي.

واجهات Repository تعزل الواجهة عن وسيلة التخزين. المصدر يطبق نماذج 01 وقواعد requirements ويستقبل Clock قابلاً للحقن. اختيار مكتبة التخزين ضمن الخطوة الثالثة، بشرط العمل دون شبكة واستمرار البيانات بعد إعادة التشغيل.

## عقد العمليات

| العملية | المدخلات والسلوك |
|---|---|
| select_demo_account / sign_out / restore_session | معرف الحساب الجاهز عند الاختيار؛ الدور من البيانات المحلية. |
| update_name | اسم جديد لصاحب الجلسة فقط. |
| list_services / list_eligible_staff | الكتالوج النشط للزائر؛ المدير يرى الجميع. |
| get_available_slots | خدمة وموظف وتاريخ محلي؛ خانات دون بيانات الآخرين أو أسباب الغياب. |
| create_booking | service_id وstaff_id وstarts_at فقط؛ اشتقاق المالك والنهاية والسعر والعملة والحالة بعد التحقق. |
| cancel_booking | معرف الحجز وسبب عند المدير؛ فحص الدور والملكية والحالة والوقت وحفظ سجل الإلغاء. |
| complete_booking | معرف الحجز؛ الموظف المخصص أو المدير، confirmed وبعد النهاية. |
| admin_manage_* | فحص admin وسلامة العلاقات والدوام ورفض تعارضات D-05. |
| reset_demo_data | إجراء صريح يعيد seed ويمسح الجلسة. |

## الحفظ والتداخل

- تحميل النسخة المحفوظة أو seed عند أول تشغيل فقط، مع إصدار لتنسيق التخزين ومعالجة أخطاء القراءة دون فقد صامت.
- تسلسل التحقق والتعديل والحفظ داخل نفس مثيل المصدر لمنع سباق الطلبات المحلية.
- لا نجاح قبل اكتمال الحفظ؛ فشل الحفظ لا يترك تحديثاً جزئياً أو حالة ناجحة ظاهرياً.
- معرفات فريدة ومراجع سليمة وزوج ربط فريد؛ منع تداخل confirmed/completed وفترات الدوام.
- لا تغيير للسعر والعملة التاريخيين عند تعديل الخدمة.
- أدوات اختبار لتأخير القراءة وفشل القراءة والكتابة وفقدان الرد بعد الحفظ.

## حدود الضمان

البيانات والجلسة والساعة المحلية قابلة للتعديل من مالك الجهاز. الاختبارات تثبت المحاكاة فقط؛ RLS وJWT وGRANTS وRPC وEXCLUDE وTIMESTAMPTZ والمعاملات بين الأجهزة تخص مرحلة الخادم المؤجلة. تحفظ اللحظات محلياً UTC وتفسر ساعات المركز وفق IANA.
