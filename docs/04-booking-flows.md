# تدفقات الحجز — النسخة التجريبية

> الإصدار 1.1؛ المرجع 06-decisions.md. Clock محلي قابل للحقن بدلاً من ساعة خادم.

## دورة الحالة

الإنشاء الصحيح → confirmed.
confirmed → cancelled: المالك عند البداية >= الآن + ساعتين، أو المدير عند الآن < البداية مع سبب إلزامي.
confirmed → completed: الموظف المخصص أو المدير عند الآن >= النهاية.
cancelled وcompleted نهائيتان؛ لا إعادة تأكيد أو تعديل وقت أو خدمة أو موظف، ولا حذف حجز من الواجهة.

## التوافر

1. اختيار خدمة نشطة وموظف مؤهل نشط وتاريخ بتوقيت Asia/Damascus.
2. استخراج يوم الأسبوع ISO وفترات الدوام المحلية غير المتداخلة.
3. خانات 30 دقيقة من بداية كل فترة؛ دوام 09:15–10:15 ينتج 09:15 و09:45.
4. الخانة كاملة في فترة واحدة دون إجازة أو confirmed/completed؛ النطاق [start,end) يسمح بالتجاور.
5. رفض البداية <= الآن أو >= بداية اليوم الحادي والثلاثين التالي محلياً؛ الحد يعتمد أيام التقويم لا إضافة 30×24 ساعة.
6. تحويل IANA دون إزاحة ثابتة، وعدم توليد وقت محلي غير موجود أو تكرار وقت ملتبس بصمت إن وجدت حواف انتقال زمني.
7. إعادة خانات فقط دون تفاصيل حجوزات الآخرين أو أسباب الإجازات.

## التأكيد

View → ViewModel → Repository → LocalFakeDataSource. الطلب يحمل الخدمة والموظف والبداية فقط. المصدر يتحقق من جلسة customer والأهلية والوقت والدوام والإجازة والتعارض، ويحسب المالك والنهاية والسعر والعملة والحالة، ويحفظ ثم يعيد المعرف.

التوافر استرشادي ويعاد فحصه. تسلسل عمليات المصدر يمنع تداخل طلبين في نفس المثيل وينتج نجاحاً واحداً على الأكثر؛ لا يثبت التزامن بين الأجهزة.

## الإلغاء والإكمال

تفحص كل عملية الجلسة والملكية والحالة والوقت. إلغاء الزبون عند ساعتين بالضبط مسموح؛ قبل ساعة و59 دقيقة مرفوض برسالة تواصل مع الإدارة. المدير يلغي قبل البداية فقط بسبب غير فارغ مع cancelled_by وcancelled_at وcancellation_reason. الإكمال عند النهاية بالضبط مسموح وقبلها مرفوض. تكرار العملية على حالة نهائية مرفوض.

## تغييرات الإدارة

قبل تغيير الدوام أو إضافة إجازة أو تعطيل موظف/خدمة أو فك الربط، يفحص المصدر حجوزات confirmed المستقبلية المتأثرة. وجودها يرفض التغيير كله ويعيد القائمة للمدير؛ لا إلغاء آلي أو إعادة جدولة. تمنع فترات الدوام المتداخلة، وتدعم الإجازات متعددة الأيام. التاريخ والأسعار والعملات محفوظة.

## الأخطاء والاستعادة

فئات مقترحة: AUTH_REQUIRED وINVALID_SLOT وSTAFF_UNAVAILABLE وSERVICE_UNAVAILABLE وSLOT_TAKEN وPERSISTENCE_ERROR وRESPONSE_UNKNOWN؛ يترجمها Repository لرسائل عربية.

تحاكى القراءة البطيئة والفشل وفقد الرد بعد الحفظ. عند فقد الرد يبحث التطبيق في حجوزات صاحب الجلسة عن الخدمة والموظف والبداية قبل إعادة الطلب؛ لا يفترض فشل العملية ولا يكرر الحجز. تظهر Loading وEmpty وError ويحدث العرض من المصدر بعد النجاح. لا شبكة مطلوبة.
