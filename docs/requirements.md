# متطلبات موعدي — النسخة التجريبية المحلية

> الإصدار 1.1؛ اعتماد المستخدم: 2026-10-22. المرجع: 06-decisions.md و05-acceptance-tests.md.

## النطاق

تطبيق Android باستخدام Flutter وDart وGetX وMVVM بتنظيم Feature-first لمركز واحد وأربعة موظفين تجريبيين. يعتمد Repository ومصدر بيانات وهمي محلي مع حفظ التغييرات بعد إعادة التشغيل وإعادة ضبط صريحة. لا Supabase SDK أو إعدادات أو مفاتيح أو اتصال خارجي أو migrations.

داخل النطاق: حسابات جاهزة وتبديل الأدوار، الخدمات والموظفون، التوافر والحجز والإلغاء والإكمال، إدارة الكتالوج والدوام والإجازات، وإحصاءات أعداد الحالات. العربية وRTL وتقويم ميلادي ووقت 24 ساعة.

خارج النطاق: التسجيل الحقيقي وتأكيد البريد والخادم والدفع والفروع وتعدد الخدمات والمدة المتغيرة وإعادة الجدولة وحجز المدير نيابة عن الزبون وحذف الحساب والرسائل الخارجية وإصدار iOS.

## المتطلبات غير الوظيفية

NFR-01: View → ViewModel → Repository → LocalFakeDataSource.
NFR-02: فحوص أدوار محلية، وأمان الخادم مؤجل.
NFR-03: لا أسرار أو SDK أو إعداد Supabase أو شبكة خارجية.
NFR-04: اختبار التداخل في نفس مثيل المصدر دون ادعاء ضمان بين الأجهزة.
NFR-05: لحظات UTC وحساب IANA وClock قابل للحقن؛ وقت الجهاز غير موثوق للإنتاج.
NFR-06: تغييرات صغيرة وتوقف بعد كل خطوة. إعداد Git ضمن التأسيس إذا لم يوجد.
NFR-07: اختبار منطق ViewModels وRepository دون شبكة.
NFR-08: العربية وRTL على أحجام Android مختلفة.
NFR-09: المالك والدور والسعر والحالة لا تؤخذ من طلب غير مقيد.
